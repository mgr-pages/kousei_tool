# 校正ツール

原稿（朱書き）と成果物のPDFを照合し、確認が必要な箇所を一覧にするツールです（旧名：朱書き照合ツール）。**原稿がなくても、成果物だけで文字・表記をチェックできます**（下の「成果物だけで見るチェック」）。原稿は、次のどれでも使えます。

- 赤字を入れた紙のスキャン
- PDFに注釈で入れた赤字
- ラフのPDF（Googleスライドなどで作ったもの、前回の印刷物に指示を書き込んだもの）
- 支給されたデータファイル：Excel（.xlsx・.xlsm）、Word（.docx・.docm）、PowerPoint（.pptx・.pptm）、テキスト（.txt）、CSV（.csv・.tsv）。価格表などが成果物に正しく載っているかを確かめられます

修正前のPDFは要りません。種類の違う原稿を混ぜて登録してもかまいません（例：ラフのPDF＋価格表のExcel）。

**旧版（前回の成果物のPDF）を任意で入れる**と、前回からの変化が指示によるものかも確かめます（原稿のない部分で旧版から変わった所を「指示にない変更」として出し、旧版から変わっていない所は「前回のまま」として一覧から外す）。

あわせて、**成果物だけを読んで**、問題がありそうな所（ページの端に残ったデータの切れ端・仕上がり線にかかる文字、日付と曜日の食い違い・かっこの閉じ忘れ・助詞の続き方・誤字や誤用・送りがな・表記ゆれ・ら抜き言葉・英語のつづりなど）も挙げます。原稿を入れずに成果物だけを入れると、このチェックだけを行います（「成果物だけチェック」。旧版も入れると、前回から変わった所も出します）。

- **Web版**：<https://mgr-pages.github.io/kousei_tool/> を開くだけで使えます（GitHub Pages。中身は `dist/校正ツール.html` と同じ）。
- **手元で使う**：`dist/校正ツール.html` を**ダブルクリックで開くだけ**で動きます（サーバー・インストール不要。ネットにつながっていなくても動く）。部品と辞書をすべて埋め込んであるため、ファイルは約41MBあります（Web版も初めて開くときにこの大きさを読み込みます）。
- どちらでも、ファイルはそのパソコンのブラウザの中だけで処理され、**外部には送信されません**。Web版も、ページを読み込んだあとは通信しません（読み込んだファイルを置いておく所・集める仕組みはありません）。
  - ページに「外部への通信を一切許さない」設定（Content-Security-Policy：`connect-src` などを `data:`・`blob:` だけにし、ほかの送り先・フォームの送信を禁止）を入れてあるため、ツールの部品（pdf.js・OpenCV.js を含む）が外へ送ろうとしてもブラウザが止めます
  - 公開先の GitHub には、ほかのWebサイトと同じく、ページを開いたときの通常の記録（アクセス元のIPアドレスなど）が残ります。選んだファイルの中身・名前は送られません
- 判定はすべて決まったルールで行います（生成AIは使いません。同じ入力なら同じ結果になります）。
- 動作確認は Chromium 系のブラウザ（Google Chrome、Microsoft Edge）で行っています。
- 原稿・成果物のどちらも、**複数のファイルに分けて登録できます**（リストの順にページをつなげて照合）。
- 原稿と成果物で**ページの順番・数・大きさが違っていても**かまいません。原稿の各ページが成果物のどのページのどの範囲に当たるかを、文字と画像の手がかりから自動で探します（見開きの片側に当たる、対応する成果物がない、なども判断します）。

使い方は `docs/利用ガイド.pdf` を見てください。

## できること

ページの組み合わせごとに、比べ方を自動で選びます。

- **同じレイアウト**（赤字を入れた校正紙と、それを直した成果物）：字形を重ねて比べる
- **レイアウトが違う**（ラフ・前回の印刷物への指示と、デザインした成果物）：文字データの中身を、並べ替え・改行・段組みの違いに左右されないやり方で比べる
- **データファイルの原稿**（Excel・Word など）：中身を読み取って、レイアウトが違うページと同じやり方で比べる。表は行ごと、文章は段落ごとに、成果物のどのページに載っているかを探す（1つの表が成果物の何ページかに分かれて載っていてもよい）
- **商品マスタのような表**（1行が1商品で、成果物には品番・価格・入数など一部の列だけが載るもの）：品番を成果物で探し、品番の近くに載っている列の値を商品ごとに比べる（下の「表の商品ごとの照合」）

| 結論 | 意味 |
|---|---|
| 指示どおりになっていない | 指示（注釈のコメント・書き込み）の文字が成果物の該当箇所に見当たらない、消す指示の文字が残っている（自動で判定） |
| 直っていない | 赤字があるのに、成果物で変わっていない |
| 指示にない変更 | 赤字がないのに、成果物で変わっている（文字・組み・画像・図版・色・位置） |
| 原稿と違う | 原稿の文字と成果物の文字が違う、原稿の文字が成果物にない、原稿にない文字が成果物にある（レイアウトが違うページ・データの原稿） |
| 直し忘れ | 全体指示・以下同様で直すはずの語が、成果物に残っている |
| 文字だけ違う | 見た目は同じでも文字が違う（長音「ー」→漢数字「一」など） |
| 赤字どおり変わった | 赤字の箇所が変わっている（中身が指示どおりかを確認。引き出し線の先の書き込みも添えて表示） |
| 指示・書き込みの確認（人が判断） | 文字では判定できない原稿のコメント・指示の書き込み（後送・使う画像の指定・書式・配置など）と、成果物に残っているアタリ・未支給・「ご指示ください」などの書き込み |
| 自動で確認済み（指示どおり） | 指示どおりと自動で確かめられたもの（指示の文字が成果物にある、消す指示の文字が消えている、指示どおりの違い）。一覧には出さず、「参考も表示」で見られる |
| 読み取れない赤字 | どの文字への指示か読み取れなかった赤字（欄外の全体指示など） |
| 全体・以下同様どおり | 赤字のない箇所だが、全体指示・以下同様として変わっている |
| 成果物だけで見つけた誤り | 原稿と照らさず、成果物だけで見て誤りの可能性が高いもの：ページの端で切れた文字・仕上がりの外に残った文字（データの切れ端）・仕上がり線にかかる文字、日付と曜日の食い違い・存在しない日付、かっこの閉じ忘れ、「をを」「。。」「ありますます」「the the」のような重なり、助詞の続き方（「をが」など）、誤用・誤字の決まった言い方（「的を得る」「完壁」「一貫として」「内臓バッテリー」「使い安い」「見ずらい」「とゆう」など）、送りがなの誤り（「必らず」など）、電話番号の桁・郵便番号の形 |
| 成果物だけで見つけた確認事項（表記ゆれなど） | 成果物の中で書き方が混ざっているもの（「問い合わせ」と「問合せ」、「拭き取る」と「ふき取る」、「サーバ」と「サーバー」、「バイオリン」と「ヴァイオリン」、全角と半角の数字・英字、金額の桁区切り、「、。」と「，．」）、ら抜き言葉・さ入れ言葉、「〜たり」が1つだけの文、敬語（二重敬語・「ご利用できます」など）、重複表現（「一番最初」「第1回目」など）、語の重なり、カタカナ語の1字違い（誤字？）、半角カナ、英語の辞書にない語（つづり？）・冠詞の a と an |
| 全角・半角などの違い | 書き方だけが原稿と違う（全角・半角、波ダッシュの形など） |
| 原稿が画像の部分 | 原稿のその部分が画像（前回の印刷物を貼ったものなど）のため、文字では比べていない部分。成果物の文字を添えて示す |

各項目では、原稿と成果物を2段に並べて**違う字だけに色を付け**、切り抜きとページの枠も**違う字の位置だけ**を囲みます。紙の赤字原稿で読めなかった字は「〓」で示します。

データファイルの原稿では、次のように扱います。

- Excel：表示されているシート・行・列のセルを、**表示形式どおりの文字**（「1,280円」「2027年4月1日」「15%」「令和9年」など）にして比べる。非表示のシート・行・列は読まない。セルのコメントは「原稿の指示」として出す。結果には Excel の行番号（「12行目」）を添える
- Word：本文の段落と表。変更履歴は**反映したあとの文**で比べる（削除した文字は読まない）。コメントは「原稿の指示」として出す
- PowerPoint：スライドごとのテキストと表（非表示のスライドは読まない）
- テキスト・CSV：文字コード（UTF-8・Shift_JIS・UTF-16）を自動で見分ける
- Excel・CSV の数字は、桁区切りの「,」のあるなしを違いとしない（「1050」と「1,050」は同じ）
- 商品マスタのような表（成果物に載らない列が2列以上あり、載る列が全体の6割以下のもの。文章として対応づかなかった表も）は、商品ごとに照合する（下の「表の商品ごとの照合」）
- 数字のすぐ前後の通貨の記号だけの違い（「¥1,280」と「1,280円」）は「全角・半角などの違い」として出す（値の違いは「原稿と違う」）
- 同じ違いが表の何行にもくり返すとき（「¥」→「円」など、数字以外の違い）は1件にまとめ、すべての位置をページの表示に枠で示す
- 表が成果物の何ページかに分かれて載り、見出しの行がページごとにくり返されていても、見出しを「原稿にない文字」としない

指示（注釈のコメント・欄外の書き込み）は、文字で判定できるものは自動で判定し、判定できないものだけを人に回します。

- 指示の文から「何に直すか」「何を消すか」を読み取る：「A」→「B」、「A」を「B」に変更、「B」に修正、「B」を追加、「A」トル、取り消し線＋「トル」など（かぎかっこがなくても、短い文なら同じ形を読む）。指示の文そのもの（「目指し」など）は、直した後の文字として扱う
- 直した後の文字が成果物の該当箇所にあれば「指示どおり」、なければ「指示どおりになっていない」。消す文字が消えていれば「指示どおり」、残っていれば「指示どおりになっていない」
- 1字だけの指示は、変わった字がその字そのものでなければ、たまたまある字と見分けられないため人に回す
- 「指示どおり」と確かめた指示の近くの「原稿と違う」「原稿にない文字」で、違いが指示の文字そのものなら「指示どおりの違い」とする
- 書式の指示（太字・細字・大きく・小さく・「赤字に」などの色・改行・追い込み）は、見た目で確かめる
  - 同じレイアウトの注釈PDF：指示の付いた所の修正前と修正後の描画で、字の線の太さ（インクの割合）・字の高さ・色を比べる。改行・追い込みは、段落の始まりが指示どおりに変わったかを見る。同じ指示に結びついた変化のどれかで指示どおりになっていれば「指示どおり」
  - レイアウトが違うページ・データの原稿：取り消し線・マーカーの範囲（Wordのコメントは付いた段落）の字に対応する成果物の字で調べる。大きさはページの字の大きさの中央値に対する比が原稿より1割以上大きい（小さい）か、太字は書体の名前（なければ線の太さがページの字より25%以上太いか）、色は字の色
- 後送・使う画像の指定・揃え・字下げ・配置・写真の差し替えなどは、文字や見た目では判定できないため「人が判断」に出す

全体指示・以下同様は、手で登録しなくても赤字原稿から判断します。

- PDFの注釈：コメントの「全体…「A」→「B」」「以下同様」を読む
- 紙・PDF共通：同じ変更が2か所以上あれば全体指示とみなし、修正後に残っている同じ語を「直し忘れ」として出す。赤字どおり変わった語が修正後のほかの箇所に残っていれば「同じ語が他にもある」として出す

## 処理のしくみ

### ページの対応

原稿の各ページと成果物の各ページを、次の2つの手がかりで組み合わせます（`pairing.js`）。

- 小さく描画した画像の特徴点（ORB）の対応
- 文字データの長い一致

位置の関係（拡大縮小・平行移動）がそろう手がかりだけを数え、手がかりの多い組から決めます。

- 同じ成果物のページで範囲が重なる組は、あとのほうを捨てます。
- 似た原稿が何ページもあるときは、隣の原稿ページがすでに同じ成果物に決まっているものを少し優先します。

原稿のページ全体が成果物のページにほぼそのまま収まり、中身の位置もそろえば「同じレイアウト」です。見開きの片側に当たるときは、その部分を切り出して比べます。

### 同じレイアウトのページ

赤字原稿のページごとに、種類を自動で見分けます。

- **PDFへの注釈**（注釈があり、文字データもあるページ）：注釈を消して描画したものを修正前、注釈ありとの描画の差を赤字とし、修正前・修正後を200dpiの画像と文字データで比べる
- **紙のスキャン**（それ以外のPDFのページ・画像）：次の2段で比べる

紙のスキャンの照合：

1. スキャンを修正後の描画に重ねる（ORB特徴点の対応から相似変換を求める。文章が動いたページでも余白の位置で正しい重ね方を選ぶ）
2. 赤ペンの赤を取り除く（修正後にも印刷されている赤は残す）。修正後の描画をスキャンの紙の色・ぼけに合わせる
3. **1段目（全部挙げる）**：両方を字形に分け、字形の見た目を照合して並びを比べ（Myers法）、違いの候補をすべて挙げる。赤字の指示が付いた字は、赤で隠れて比べにくいので「変わっていない」寄りに比べる（直っていない赤字を見逃さないため）
4. **2段目（誤検出を消す）**：候補ごとに、修正後の字の枠でスキャンを切り直し、位置を合わせ直して1字ずつ比べる。スキャン側に修正後の字で説明できないインクがないかも確かめる。**同じだと確かめられた候補だけを消し**、確かめられないものは残す。赤以外の書き込み（鉛筆・黒ペン）・赤字の跡・印鑑も消す
5. 赤の形から指示箇所を読み（囲み・取り消し線・挿入記号・書き込み。引き出し線は除く）、候補と突き合わせる
6. 修正前の文字は、修正後の字のうち見た目が一致するものから推定し、全体指示・以下同様の判断に使う

### レイアウトが違うページ（内容で照合）

原稿と成果物の文字データを、字の並びとして対応づけます（`content.js`）。

1. 原稿の文字を、段落・テキストボックス・「見出し　中身」の空白で、まとまりに分ける。
2. まとまりごとに、成果物の文字の並びのいくつかの区間につなぎ合わせて対応させる。
   - 区間の中は、普通の編集（一致・置換・挿入・削除）として扱う。
   - 別の区間へ移るたびに一定の手間がかかるとして、手間の合計が最小になる対応を動的計画法で求める。そのため、段組み・配置・改行の違いでは違いにならない。
   - 原稿のまとまりが来るはずの範囲から遠い所ほど、手間を少し大きくする。同じ文が2か所にあるときは、近いほうに当たる。
3. 違う字だけを取り出す。全角・半角や波ダッシュの形など、書き方だけの違いは別に分ける。
   - 文字データには1行分の幅しかない。そこで、全角・半角の幅の割合で字に割り振り、さらに描画した字の形（インク）に合わせて、違う字の枠を字の位置にそろえる。
4. 指示として扱うのは次のもので、成果物と並べて示す。
   - 原稿の欄外の書き込み
   - 「後送」「カエ」「ファイル名」など、指示の言い方の短い書き込み
   - 注釈のコメント
   指示の文字が成果物にあれば、自動確認OKとする。
5. 成果物の文字のうち、どの原稿にも対応しなかったものは、次のように分ける。
   - 原稿が画像の位置：原稿が画像の部分
   - それ以外：原稿にない文字
6. 成果物の書き込み（ピンクの帯に白抜きの文字、「アタリ：」「未支給」「ご指示ください」など）は、照合から外して、別の項目として出す。

### データファイルの原稿

1. ファイルを読み取り（Office のファイルはZIPの中のXMLをブラウザの展開機能で読む。`docsrc.js`）、表は行ごと、文章は段落ごとの「まとまり」にして、照合用のページ（文字データと表示用の画像）を作る。
2. 原稿のまとまりの字が、成果物のどのページにそのまま含まれるかで、載っているページの候補を決める（位置の手がかりは使わない）。
3. まとまりごとに、字がいちばん多く含まれるページを選んで照合する（どのページにもないまとまりは、前後のまとまりと同じページで照合し、「成果物にない」と出す）。
4. よく一致するまとまりから決める。半分も一致しないまとまりは「成果物に載っていない」とみなす（似た別の行の字を取らないように）。表の行は、いちばん長く一致した所の行の範囲で照合する（同じ値が別の行にあっても、その行の違いを見落とさないように）。
5. PDFの原稿（ラフなど）とは別に照合する。ラフとExcelの表のように、同じ所の原稿が2つあってもよい。

### 旧版（任意）との比べ合わせ

旧版を入れたときだけ行います（`analyze.js` の `oldDiff`）。比べるのは文字データです。

1. 旧版の各ページが成果物のどのページ・範囲に当たるかを、原稿と同じやり方で求める。
2. 旧版と成果物の字を、内容で照合するページと同じやり方（厳しめ）で対応づけ、成果物の字ごとに「旧版と同じ」「旧版の別の字から変わった」「旧版にない」を、旧版の字ごとに「成果物で消えた」を求める。
3. 次のように使う。
   - 原稿のない部分（どの原稿の範囲にも入らない所）の成果物の字
     - 旧版と同じ → 「前回のまま」として1件にまとめ、一覧から外す（「参考も表示」で見られる）
     - 旧版から変わった → 「指示にない変更」。旧版の字→成果物の字で、変わった字だけに色を付ける
   - 原稿のない部分で、旧版にあった字が成果物で消えた → 「指示にない変更」
   - 原稿がまったく当たらない成果物のページの、旧版から変わった字・消えた字 → 「指示にない変更」
   - 「原稿と違う」の項目には、その所が旧版と同じ（前回のまま＝直っていない可能性）か、旧版からも変わったかを添える
   - 原稿のある部分の「原稿にない文字」には、旧版と同じか変わったかを添える（一覧からは外さない）
4. 旧版から変わった所の項目には、旧版の切り抜きも並べて示す。

画像・図版の変化は比べない（文字だけ）。同じレイアウトの赤字原稿（紙・注釈PDF）の範囲は、赤字原稿どうしで比べているため、旧版との比べ合わせには使わない。

### 表の商品ごとの照合

商品マスタのように、1行が1商品で、成果物には一部の列だけが載る表を、商品（行）ごとに比べます（`records.js`）。

- 品番の列：品番のような値（英数字と記号だけで数字を含む4字以上）が行ごとに違い、成果物にそのまま載っている値がいちばん多い列。成果物に載らない形の品番が混ざっていてもよい
- 品番を成果物で探す。そのままは見つからなければ、同じ形（英字・数字・記号の並び）で1字違い（10字以上は2字違いまで）のものを探し、「品番が違う？」として出す
- 成果物に載る列：品番が見つかった商品の6割以上で、品番の近く（同じ行、または下の数行）に値がある列（価格・入数・単位など）。数字は「15600」と「¥15,600」、「150.0」と「150」を同じとみなす
- 載る列の値が品番の近くにない商品は「（列の名前）が違う」として、ほかの商品で値があった位置にある成果物の値を並べて示す
- 成果物に見当たらない商品は、表の並びで続くものを1件にまとめる。すべて一致した商品は1件にまとめて「自動で確認済み」にする（一覧には出さない）
- 原稿の表示は、照合に使った列（品番と載る列）だけの表にする

### 成果物だけで見るチェック

原稿があるときは照合の最後に、原稿がないとき（成果物だけを入れて「成果物だけチェック」を押したとき）はこれだけを行います。原稿がないときは、ページの対応づけを行わず、項目のある成果物のページを「成果物だけ」のページとして、成果物のページの順に示します。

成果物の文字データだけを読み、決まったルールと辞書で判定します（`jcheck.js`・英語は `echeck.js`。生成AIは使いません）。

辞書は、日本語が形態素解析の kuromoji.js と辞書 IPADIC、英語が SCOWL 由来の Hunspell 辞書（en_US。組み立てのときに活用形まで広げた約12万語の一覧）です。どちらもHTMLに埋め込んであり、外部は読みに行きません（日本語の辞書は、照合の最後に1〜2秒で読み込みます）。

- ページの端の文字：ページの外枠をまたぐ文字（ページの端で切れている）、仕上がり（TrimBox）の外にある文字（断裁で落ちる。ほかのページや作業中のデータの切れ端）、仕上がり線をまたぐ文字（断裁で切れる）を出す。仕上がりの範囲はPDFに書かれたもの（トンボ付きで書き出したPDF）を読む。仕上がりの外の文字のうち、ファイル名・日時などの印刷用の情報（決まった形の文字か、ほかのページの同じ高さに同じ形の文字があるもの）は除く。切れ端と仕上がりの外の文字は、ほかのチェック（かっこの対応など）では読まない
- 日付と曜日：「2027年6月1日（水）」「5/10(月)」「〜22日（月）」（月は前の日付から）などの曜日を計算して比べる。年のない日付は、成果物にいちばん多く出てくる年で計算する（成果物に年がひとつもなければ、今年と来年のどちらでも合わないときだけ出す）。曜日がなくても、存在しない日付（「2月30日」「4月31日」）は出す（年のない「2月29日」は出さない）
- かっこ：開きと閉じの対応を調べる。全角と半角のかっこは組にしてよい。「1）」「a)」のような番号の閉じかっこは数えない。「見出し　中身」の空白で分かれたまとまりは、次のまとまりまで続けて探す
- 重なり：「をを」「がが」「。。」「、。」、助動詞の「ありますます」など。同じ語（漢字2字以上・カタカナ3字以上、かなを含む語の並び「ご利用ご利用」）がすぐ続くもの（確認だけ。同じ文字列のまとまりの中だけ）
- 助詞の続き方（辞書）：格助詞の「が」「を」がほかの格助詞と続くもの（「をが」「がを」「にを」など。「からが」「とを」は正しいので除く）
- 誤用・誤字：「的を得る」「汚名挽回」「一同に会す」など誤用とはっきり分かる言い方、「完壁」「専問」「価値感」「一貫として」「品質保障」「対照年齢」「内臓バッテリー」「始めまして」などの誤字・誤変換、四字熟語の誤り（「絶対絶命」「危機一発」など）、かな遣い（「とゆう」「こんにちわ」「見ずらい」）、「使い安い」（動詞のあとの「安い」。辞書で動詞かを確かめ、「高い安い」は除く）。ほかの読み方・使い方がまずないものだけの一覧
- 送りがなの誤り：「短かい」「明かるい」「新らしい」「必らず」「少い」「確める」など（許容されている書き方は除く）
- ら抜き言葉（辞書）：一段・カ変の動詞＋「れる」（「食べれる」「来れる」）。可能動詞＋「れる」（「行けれる」）は「れ足す言葉」として出す。さ入れ言葉（「読まさせて」）。確認だけ
- 「〜たり」（辞書）：文の中に「〜たり」が1つだけのもの（「〜たりする」は除く）。確認だけ
- 敬語・重複表現（確認だけ）：二重敬語（「お〜になられる」「おっしゃられる」「拝見させていただく」など）、謙譲語＋れる（「申される」）、「ご利用できます」のような「ご〜できる」、重複表現（「一番最初」「まだ未定」「第1回目」「約〜程度」など）
- 電話番号（市外局番から10桁、携帯・IP電話は11桁、0120は10桁、0800は11桁）・郵便番号（3桁-4桁）の形
- 表記ゆれ（確認だけ）：少ないほうの書き方の所を代表にし、すべての位置を示す
  - 送りがなの一覧（「問い合わせ」と「問合せ」など）
  - 辞書の読み：読みと品詞が同じ語で、送りがなだけが違う・漢字とかなが違う書き方（「拭き取る」「ふき取る」「ふきとる」、「時」と「とき」など）。読みが同じでも漢字が違う語（「機会」と「機械」）、複合語（「取扱説明書」）、補助動詞（「〜ていく」）、「〜について」「〜によって」などは数えない
  - カタカナ語の長音（「サーバ」と「サーバー」）、ヴ・ウィなど（「ヴァイオリン」と「バイオリン」）
  - 全角と半角の英字、金額の桁区切りの「,」のあるなし（4桁以上の金額）、句読点（「、。」と「，．」）
- カタカナ語の1字違い（確認だけ）：1か所だけのカタカナ語（5字以上）で、2か所以上ある語と1字だけ違うもの（「フローリンク」と「フローリング」）
- 半角カナ（確認だけ）
- 英語（`echeck.js`）
  - つづり（確認だけ）：辞書にない語。2字以下、大文字だけの5字以下（略語）、途中に大文字がある語（「iPhone」）、数字に続く語（品番）、URL・メールアドレス、成果物に3回以上出てくる語、カタカナの読みや®・™が付いた語（「Lumora（ルモラ）」）、大文字で始まるローマ字の語（「Kousei」）は見ない。ハイフンでつないだ語は分けて調べる。1字違いの候補を添える
  - 同じ語の重なり（「the the」。よく使う短い語は直す必要がありそう、それ以外は確認だけ。「had had」などは除く）
  - 冠詞の a と an（確認だけ。「an hour」「a university」などの音の決まりを見る。u で始まる語の多くと略語は見ない）
  - 日付と曜日（「Monday, October 26, 2027」「Oct. 26 (Mon)」「Monday 26 October」）と、存在しない日付（「February 30」）
  - PDFの文字データには語の間の空白がないため、元の空白・文字列のまとまりの間のすきま・行の変わり目から語の切れ目を戻して読む
- 飾りのために少しずらして重ねて描いた文字（影・縁取り）は、文字データを読むときに1つにする

文体（です・ます／だ・である）の混在や、意味の上での不自然さは見ません（チラシでは見出しとの混在がふつうにあり、決まったルールでは見分けられないため）。

- 指示にない変更

|---|---|---|---|---|---|---|
| 紙の赤字原稿 s1〜s8 | 39〜41件 | **0件** | 0〜1件 | 0〜4件 | 1〜4件 | 約115〜135秒 |

  - 赤字の斜線でほとんど隠れた「1年→2年」「（水）→（火）」。直っているのに「直っていない」と出た（見逃さない側の誤り）

- 誤検出は、欄外の小さい字（柱・ページ番号）と、赤字の書き込みが本文の行にかかった所です。
- 「読み取れない赤字」に残るのは、欄外の全体指示（「全体的に「お問い合わせ」→「お問合せ」」）など、どの文字にも結びつかない書き込みです。

## 分かっている限界

- 紙の手書きの文字（何に直すか、「全体的に」「ママ」「イキ」など）は読めない。全体に関わる直しは、同じ直しが複数あることから判断する。「ママ」は「直っていない」と出る
- 紙では、見た目がほぼ同じ別の字への差し替え（「ー」と「一」など）は、カタカナの中の漢数字のように形から分かるものしか見つけられない（PDFの注釈なら文字データで見つける）
- 赤字で字がほとんど隠れた箇所（取り消し線・斜線の下の小さい字など）は、直っていても「直っていない」と出ることがある（直っていない赤字を見逃さない側に倒している）
- 改行・追い込みの指示は、紙では読み取れないことがある
- 引き出し線が文字の行の真ん中を、行に沿って通ると、取り消し線と見分けられないことがある
- 赤い写真・赤い背景の上の赤字は抽出しにくい
- 本来の縦書きフォント（縦書き用のCIDフォント）を使ったPDFの文字位置は、まだ実データで確かめていない
- レイアウトが違うページで比べられるのは文字データだけ。次の部分は、文字では比べられない。
  - 成果物の文字がアウトライン化・画像化されている部分
  - 原稿が画像の部分（前回の印刷物を貼ったものなど）
  原稿が画像の部分は「原稿が画像の部分」として、成果物の文字を添えて示す
- レイアウトが違う紙の原稿（手書きのラフのスキャン）は、文字を読めないため比べられない
- 原稿の書き込みが引き出し線で指す先は読まない（書き込みの位置と、成果物のおよその位置を並べて示す）
- 紙のスキャンの照合は1ページあたり20〜30秒ほどかかる（パソコンの性能による）
- データファイルの原稿について：
  - 古い形式（.xls・.doc・.ppt）は読めない。Excel・Word・PowerPoint で新しい形式（.xlsx・.docx・.pptx）かPDFに保存し直してから使う
  - パスワード付きのファイルは読めない
  - Excel の数式のセルは、ファイルに保存されている計算結果を使う（Excelで保存したファイルなら最新の値）。分数の表示形式は標準の表示で比べる。グラフ・図形・画像の中の文字は読まない
  - Word は本文だけを読む（ヘッダー・フッター・脚注は読まない）。テキストボックスの文字は、置かれた段落の文字として読む
  - PowerPoint は図形のテキストと表だけを読む（グラフ・SmartArt・ノートは読まない）
  - テキスト・CSV の文字コードは UTF-8・Shift_JIS・UTF-16 だけ（EUC-JP などは読めない）
  - データファイルの中の画像は比べない。比べるのは文字だけ
  - 成果物に同じ表が2か所あるときは、片方を「原稿にない文字」と出す
- 旧版との比べ合わせは文字だけ（画像・図版の差し替えは比べない）。旧版と成果物のレイアウトが大きく違うと、ページ・範囲の対応が取れないことがある
- 書式の指示で自動で判定するのは、太字・細字・大きさ・色の名前のある色・改行・追い込みだけ。揃え・字下げ・位置・行間などは人が判断する。紙の赤字原稿の書式の指示（手書き）は読めない
- 表の商品ごとの照合は、品番が英数字の表だけ（品番が日本語の名前だけの表は、文章として照合する）。成果物に載る列は、品番の近く（同じ行か下の数行）に値があるものだけを見る（離れた所の表・別のページの価格表などは見ない）
- ページの端の文字は文字だけを見る（画像・図形の切れ端は見ない）。仕上がりの範囲が書かれていないPDFでは、ページの外枠をまたぐ文字だけを見る
- 成果物だけで見るチェックは、決まったルールと辞書で判定できるものだけ。意味の上での不自然さ・文体の混在・一覧にない誤用、辞書にある別の語になってしまう誤字（「階段」を「階投」とするなど）は見つけられない。年の書いていない日付は、成果物に出てくる年で計算する
- 辞書の区切りが正しくない語（「申込み」など）は、辞書を使うチェック（表記ゆれ・ら抜き言葉など）で見落とすことがある。送りがなの表記ゆれのよく出るものは一覧でも見ている
- 英語のつづりのチェックは、辞書（米国のつづり）にない語を出すだけ。英国のつづり（「colour」）・専門用語・固有名詞も「辞書にない語」として出ることがある（確認だけ）。英語の文法は見ない
- ページの数が多いと、ページの対応を調べる時間が増える（原稿と成果物のページ数が同じで、同じ順番のページが同じレイアウトなら、ほかの組み合わせは調べない）
