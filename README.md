# 朱書き照合ツール

初校PDF・朱書き（紙のスキャン、またはPDFへの注釈）・修正後PDFを照合し、確認が必要な箇所を一覧にするツールです。

- **Webで使う**：https://mgr-pages.github.io/kousei_tool/ を開く（GitHub Pages）
- **ファイルで使う**：`dist/朱書き照合ツール.html` を**ダブルクリックで開くだけ**（インターネット接続も不要）
- どちらの場合も、選んだPDFはそのパソコンのブラウザの中だけで処理され、**外部には送信されません**（Webの場合も、通信するのはアプリ本体の読み込みだけ）。
- 判定はすべて決まったルールで行います（生成AIは使いません。同じ入力なら同じ結果になります）。
- 動作確認は Chromium 系のブラウザ（Google Chrome、Microsoft Edge）で行っています。

使い方は `docs/利用ガイド.pdf`、または画面の「使い方と注意点」を見てください。

## リポジトリの構成

| 場所 | 中身 |

| `test-kit/` | テストキット：ダミー原稿・赤字指示書・正解表・実施手順書、採点スクリプト、検証用のPython版（`test-kit/tool`） |
| `testdata/` | 自動テストの入力（ダミー原稿と、模擬の朱書き：紙8通り・PDF注釈1通り） |

## できること

| 判定 | 意味 |
|---|---|
| 修正漏れの疑い | 赤字があるのに、修正後で変わっていない |
| 指示外の変更 | 赤字がないのに、修正後で変わっている（文字・組み・画像・図版・色・位置） |
| 全体指示・以下同様の展開漏れ | 全体指示や「以下同様」が、他の箇所に反映されていない |
| 文字データだけの差し替え | 見た目ではほぼ同じだが、文字データが違う（長音「ー」→漢数字「一」など） |
| 赤字どおり変更あり | 赤字の箇所が変わっている。中身は人が確認（PDFの注釈なら、指示文と自動で照合） |
| 指示箇所に結びつかない赤字 | 欄外の注記・印鑑など。人が読む |

## 処理のしくみ

1. 初校と修正後を200dpiの画像にし、文字のまとまり（ブロック）→ 行 → 1字ずつの字形に分ける
2. 字形の見た目（形・太さ・色・行内の位置）を照合して番号を振り、並びを最小の差分（Myers法）で比べる → 変更箇所
3. 写真・図版は同じ見た目を修正後から探す → 変化・移動・削除
4. 朱書きの赤を取り出す（紙：スキャンを初校に重ねてから赤を抽出／注釈：注釈の位置情報と描画差分）
5. 赤の形から「どこを指しているか」を読む（囲み・取り消し線・挿入記号・画像への書き込み）。行を突き抜けるだけの線や行間を走る線は引き出し線として除く
6. 変更箇所と指示箇所を突き合わせ、全体指示・以下同様の展開を確かめ、PDFの文字データで見た目に出ない差し替えを裏取りする

## ファイル構成

| ファイル | 役割 |
|---|---|
| `src/index.html` | 画面（HTMLとCSS） |
| `src/js/util.js` | 共通処理（画像・2値マスク・連結成分） |
| `src/js/myers.js` | 最小の差分（Myers法） |
| `src/js/pdfio.js` | PDFの読み込み・描画・文字データ・注釈（pdf.js） |
| `src/js/vision.js` | 見た目による変更検出（ブロック分割・読み順・字形の照合・画像の比較） |
| `src/js/marks.js` | 朱書きの取得と解釈（スキャンの位置合わせ・赤の抽出・指示箇所の読み取り） |
| `src/js/analyze.js` | 照合の本体（突き合わせ・展開・裏取り・結果の一覧） |
| `src/js/ui.js` | 画面の動き（入力・一覧・ページ表示・確認状態・出力） |
| `build.js` | 部品をすべて1つのHTMLに埋め込む |
| `test/run.js`・`test/suite.sh` | 自動テスト（ブラウザで照合し、正解表で採点） |

判定のしきい値（例：字形を同じとみなす差 75、行を突き抜ける線の長さ 0.6字分など）は `vision.js` と `marks.js` にあります。変えたときは必ず自動テストを通してください。

## Webでの公開（GitHub Pages）

リポジトリの Settings → Pages で、Source を「Deploy from a branch」、Branch を「main」「/ (root)」にしています。main を更新すると数分でWeb版も更新されます。

- Webで公開されるのはリポジトリ全体です（テストデータはダミーのみ。実際の原稿はリポジトリに入れないでください）。
- 確認の状態（OK・要修正・メモ）は、ブラウザに保存されます。Web版とファイル版では保存先が別になります。

## 作り直し方

```sh
npm ci                      # pdfjs-dist 4.10.38 / @techstark/opencv-js 4.10.0-release.1（版は固定）
npm run build               # → dist/朱書き照合ツール.html（部品をすべて埋め込んだ1ファイル）
```

ネットワークが要るのは `npm ci` のときだけです。できあがったHTMLは、外部のファイルやサーバーを一切読みに行きません。

## 自動テスト

テストキット（`test-kit`）の正解表・採点スクリプトと、テストデータ（`testdata`）を使います。

```sh
npm install --no-save playwright && npx playwright install chromium   # テストのときだけ必要
npm run build
bash test/suite.sh testdata test-kit/tool/gt.json test-kit/tool/evaluate.py out
```

- 紙の模擬朱書き8通り（`s1〜s8`：筆跡の揺れ・スキャンの傾き・汚れを乱数で変えたもの）と、PDF注釈の朱入れ1通りを照合し、正解表（41項目）で採点します。採点には Python 3 が要ります。
- テストデータは `old.pdf`・`new.pdf`（`test-kit` の `01_初校ダミー.pdf`・`03_修正後ダミー.pdf` と同じもの）・`s1〜s8/T1_scan.pdf`・`T1_digital.pdf` です。作り直すときは `test-kit/tool/simulate.py` を使います。
- Playwright は日本語を含むファイルパスを読めないことがあるため、テストデータは英数字のファイル名にしています（画面からファイルを選ぶ通常の使い方には影響しません）。
- 判定のしきい値を変えたときは、「重大な見逃し」が0件のままであることを必ず確かめてください。
- `test-kit/tool` のPython版は、同じ判定を実装した検証用の版です。判定を変えたときはこちらもそろえておくと、結果を突き合わせて確かめられます（使い方は `test-kit/tool/README.md`）。

### 納品時点の結果（2026年10月23日）

正解表の41項目に対する成績です。「重大な見逃し」は、修正漏れ・展開漏れ・指示外の変更・文字データだけの差し替えを見落とすこと（指示外の変更を「赤字どおり」と扱うことも含む）で、採点の基準は `test-kit/tool/evaluate.py` にあります。

| 入力 | 合格 | 重大な見逃し | 既知の限界 | 誤検出 | 1回の処理時間 |
|---|---|---|---|---|---|
| 紙の朱書き s1〜s8 | 39〜41件 | **0件** | 0〜1件 | 0〜3件 | 34〜38秒 |
| PDFへの注釈 | 41件 | **0件** | 0件 | 0件 | 20〜21秒 |

- 合格にならなかったのは、ごく小さな挿入記号（くさび）を読み取れなかったもの（「指示外の変更」と「人が読む赤字」として出るため、見落としにはならない）と、紙の「ママ」（既知の限界）です。
- 誤検出（正解表にない指摘）は、模擬の朱書きで引き出し線が本文の行を通る箇所と、手書きの注記が本文に重なる箇所です。どちらも「修正漏れの疑い」として人に確認を求める、安全側の誤りです。
- 処理時間は、クラウド上の検証環境（Chromium）で4ページを照合したときのものです。
- Python版（`test-kit/tool`）でも、9通りすべてで重大な見逃し0件、合格39〜41件でした。

## 分かっている限界

- 紙の「ママ」「イキ」（変更しない指示）は読めないため、「修正漏れの疑い」と出る（PDFの注釈なら読める）
- 引き出し線が文字の行の真ん中を、行に沿って通ると、取り消し線と見分けられないことがある（「修正漏れの疑い」と出る安全側の誤り。行のほぼ全長にわたる細い線は「引き出し線の可能性」と添えて、一覧の後ろに回す）
- 本文に重なった手書きの注記や、ごく小さな挿入記号は読み取れないことがある（読み取れなかった挿入は「指示外の変更」と「人が読む赤字」として出る）
- 紙の手書きの指示文（「目指し」などの赤字の中身）は読めない。中身の確認は人が行う
- 赤い写真・赤い背景の上の赤字は抽出しにくい
- 文字データのない（アウトライン化した）PDFでは、文字データでの裏取り・全体指示の検索はできない（見た目の比較は動く）
- 本来の縦書きフォント（縦書き用のCIDフォント）を使ったPDFの文字位置は、まだ実データで確かめていない
- 処理時間の目安は4ページで約20〜40秒（パソコンの性能による）。ページ数が多いと時間とメモリが増える
