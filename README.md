# 朱書き照合ツール

赤字原稿（紙のスキャン、またはPDFへの注釈）と修正後PDFを照合し、確認が必要な箇所を一覧にするツールです。修正前のPDFは要りません。

- `dist/朱書き照合ツール.html` を**ダブルクリックで開くだけ**で動きます（サーバー・インストール不要）。
- ファイルはそのパソコンのブラウザの中だけで処理され、**外部には送信されません**。
- 判定はすべて決まったルールで行います（生成AIは使いません。同じ入力なら同じ結果になります）。
- 動作確認は Chromium 系のブラウザ（Google Chrome、Microsoft Edge）で行っています。
- 赤字原稿・修正後PDFのどちらも、**複数のファイルに分けて登録できます**（リストの順にページをつなげて照合）。

使い方は `docs/利用ガイド.pdf` を見てください。

| `testdata/` | 自動テストの入力（修正後のダミー原稿 `new.pdf` と、模擬の赤字原稿：紙のスキャン8通り・PDF注釈1通り。`split/` は複数ファイルの確認用に分割したもの） |

## できること

| 結論 | 意味 |
|---|---|
| 直っていない | 赤字があるのに、修正後で変わっていない |
| 指示にない変更 | 赤字がないのに、修正後で変わっている（文字・組み・画像・図版・色・位置） |
| 直し忘れ | 全体指示・以下同様で直すはずの語が、修正後に残っている |
| 文字だけ違う | 見た目は同じでも文字が違う（長音「ー」→漢数字「一」など） |
| 赤字どおり変わった | 赤字の箇所が変わっている（中身が指示どおりかを確認。引き出し線の先の書き込みも添えて表示） |
| 読み取れない赤字 | どの文字への指示か読み取れなかった赤字（欄外の全体指示など） |
| 全体・以下同様どおり | 赤字のない箇所だが、全体指示・以下同様として変わっている |

各項目では、修正前と修正後を2段に並べて**違う字だけに色を付け**、切り抜きとページの枠も**違う字の位置だけ**を囲みます。紙の赤字原稿で読めなかった字は「〓」で示します。

全体指示・以下同様は、手で登録しなくても赤字原稿から判断します。

- PDFの注釈：コメントの「全体…「A」→「B」」「以下同様」を読む
- 紙・PDF共通：同じ変更が2か所以上あれば全体指示とみなし、修正後に残っている同じ語を「直し忘れ」として出す。赤字どおり変わった語が修正後のほかの箇所に残っていれば「同じ語が他にもある」として出す

## 処理のしくみ

赤字原稿のページごとに、種類を自動で見分けます。

- **PDFへの注釈**（注釈があり、文字データもあるページ）：注釈を消して描画したものを修正前、注釈ありとの描画の差を赤字とし、修正前・修正後を200dpiの画像と文字データで比べる
- **紙のスキャン**（それ以外のPDFのページ・画像）：次の2段で比べる

紙のスキャンの照合：

1. スキャンを修正後の描画に重ねる（ORB特徴点の対応から相似変換を求める。文章が動いたページでも余白の位置で正しい重ね方を選ぶ）
2. 赤ペンの赤を取り除く（修正後にも印刷されている赤は残す）。修正後の描画をスキャンの紙の色・ぼけに合わせる
3. **1段目（全部挙げる）**：両方を字形に分け、字形の見た目を照合して並びを比べ（Myers法）、違いの候補をすべて挙げる。赤字の指示が付いた字は、赤で隠れて比べにくいので「変わっていない」寄りに比べる（直っていない赤字を見逃さないため）
4. **2段目（誤検出を消す）**：候補ごとに、修正後の字の枠でスキャンを切り直し、位置を合わせ直して1字ずつ比べる。スキャン側に修正後の字で説明できないインクがないかも確かめる。**同じだと確かめられた候補だけを消し**、確かめられないものは残す。赤以外の書き込み（鉛筆・黒ペン）・赤字の跡・印鑑も消す
5. 赤の形から指示箇所を読み（囲み・取り消し線・挿入記号・書き込み。引き出し線は除く）、候補と突き合わせる
6. 修正前の文字は、修正後の字のうち見た目が一致するものから推定し、全体指示・以下同様の判断に使う

## 作り直し方

```sh
npm ci                      # pdfjs-dist 4.10.38 / @techstark/opencv-js 4.10.0-release.1（版は固定）
npm run build               # → dist/朱書き照合ツール.html（部品をすべて埋め込んだ1ファイル）
```

ネットワークが要るのは `npm ci` のときだけです。できあがったHTMLは、外部のファイルやサーバーを一切読みに行きません。

## 自動テスト

```sh
npm install --no-save playwright && npx playwright install chromium   # テストのときだけ必要
npm run build
bash test/suite.sh testdata test-kit/tool/gt.json test-kit/tool/evaluate.py out
```

- 紙の模擬赤字原稿8通り（`s1〜s8`：筆跡の揺れ・スキャンの傾き・汚れを乱数で変えたもの）と、PDF注釈の赤字原稿1通りを、修正後PDF（`new.pdf`）と照合し、正解表（41項目）で採点します。採点には Python 3 が要ります。
- 複数ファイルの確認として、`testdata/split` の分割したPDF（スキャン2ファイル・注釈2ファイル・修正後2ファイル）をばらばらの順で渡し、1ファイルのとき（s1・注釈）と判定が完全に同じになるかも確かめます。
- `testdata/old.pdf` は模擬の赤字原稿を作ったときの元の原稿です（照合には使いません）。作り直すときは `test-kit/tool/simulate.py` を使います。
- 判定のしきい値を変えたときは、「重大な見逃し」が0件のままであることを必ず確かめてください。

### 結果（2026年10月26日）

正解表の41項目に対する成績です。「重大な見逃し」は、直っていない赤字・直し忘れ・指示にない変更・文字だけの差し替えを見落とすこと（指示にない変更を「赤字どおり」と扱うことも含む）で、採点の基準は `test-kit/tool/evaluate.py` にあります。

| 入力 | 合格 | 重大な見逃し | 既知の限界 | 誤検出 | 読み取れない赤字 | 1回の処理時間（4ページ） |
|---|---|---|---|---|---|---|
| 紙の赤字原稿 s1〜s8 | 39〜41件 | **0件** | 0〜1件 | 0〜4件 | 1〜4件 | 約90〜115秒 |
| PDFへの注釈 | 41件 | **0件** | 0件 | 0件 | 0件 | 約30秒 |

- 合格にならなかったのは、赤字の斜線でほとんど隠れた「1年→2年」「（水）→（火）」が、直っているのに「直っていない」と出たもの（見逃さない側の誤り）と、紙の「改行」「ママ」（既知の限界）です。
- 誤検出は、欄外の小さい字（柱・ページ番号）と、赤字の書き込みが本文の行にかかった所です。
- 「読み取れない赤字」に残るのは、欄外の全体指示（「全体的に「お問い合わせ」→「お問合せ」」）など、どの文字にも結びつかない書き込みです。
- 処理時間は、クラウド上の検証環境（Chromium、4コア）で、紙は4通りを同時に動かしたときのものです。

## 分かっている限界

- 紙の手書きの文字（何に直すか、「全体的に」「ママ」「イキ」など）は読めない。全体に関わる直しは、同じ直しが複数あることから判断する。「ママ」は「直っていない」と出る
- 紙では、見た目がほぼ同じ別の字への差し替え（「ー」と「一」など）は、カタカナの中の漢数字のように形から分かるものしか見つけられない（PDFの注釈なら文字データで見つける）
- 赤字で字がほとんど隠れた箇所（取り消し線・斜線の下の小さい字など）は、直っていても「直っていない」と出ることがある（直っていない赤字を見逃さない側に倒している）
- 改行・追い込みの指示は、紙では読み取れないことがある
- 引き出し線が文字の行の真ん中を、行に沿って通ると、取り消し線と見分けられないことがある
- 赤い写真・赤い背景の上の赤字は抽出しにくい
- 本来の縦書きフォント（縦書き用のCIDフォント）を使ったPDFの文字位置は、まだ実データで確かめていない
- 紙のスキャンの照合は1ページあたり20〜30秒ほどかかる（パソコンの性能による）
