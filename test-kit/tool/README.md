# 朱書き照合ツール（試作）と採点スクリプト

初校PDF・朱書き（紙のスキャン、またはPDFへのデジタル注釈）・修正後PDFを照合し、要確認の箇所を分類します。
判定はすべてルールベースです（同じ入力なら同じ結果）。生成AIや外部サービスは使わず、データは手元のPCから出ません。

> これは検証用の試作（Python）です。現場で使う版は、ブラウザでHTMLファイルを開くだけで動く静的な版（リポジトリのルート、`dist/校正ツール.html`（旧名：朱書き照合ツール））です。ここの `evaluate.py`・`gt.json`・`simulate.py` は、静的な版の自動テストでも使います。

## 必要なもの

- Python 3.10 以上
- ライブラリ：`pip install pymupdf opencv-python-headless numpy pillow`

## 使い方

```sh
cd tool

# 紙の朱書き（スキャンPDF）。rules.json は全体指示（紙の手書きは読めないため、校正者が登録する想定）
python3 proofcheck.py ../01_初校ダミー.pdf ../03_修正後ダミー.pdf --scan T1_scan.pdf --rules rules.json --out T1_結果

# デジタル朱入れ（注釈入りPDF）。全体指示・以下同様・ママは注釈の文字から自動で読み取る
python3 proofcheck.py ../01_初校ダミー.pdf ../03_修正後ダミー.pdf --digital T1_digital.pdf --out T1_デジタル結果

# 採点（正解表との突き合わせ）
python3 evaluate.py gt.json T1_結果/findings.json --rules-given --csv T1_採点.csv
python3 evaluate.py gt.json T1_デジタル結果/findings.json --digital --csv T1_デジタル採点.csv
```

出力フォルダには次のファイルができます。

- `findings.json`：判定の一覧
- `page1.jpg` 〜 `page4.jpg`：左が初校と朱書き、右が修正後。枠の色は判定の種類を表します（緑：赤字どおり変更あり、赤：修正漏れの疑い、橙：指示外の変更、黄緑：全体指示・以下同様で説明できる変更、紫：展開漏れ、水色：見た目では差が出ない差し替え、灰：人が読む赤字）

4ページで15〜20秒ほどかかります。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `proofcheck.py` | 照合の本体（変更の検出 → 赤字の解釈 → 対応づけ → 全体指示・以下同様の展開 → 文字データでの裏取り） |
| `vis.py` | 見た目（画像）で変更を検出する部分（ブロック分割、読み順、字形の切り出しと比較） |
| `glyphcmp.py` | 字形どうしの見た目の比較（0.33画素刻みの位置合わせ＋局所的な差） |
| `myers.py` | 最小の差分（Myers法）。同じ内容が繰り返される表などで、変更の位置を取り違えないため |
| `marks.py` | 赤字の取得（スキャンの位置合わせ・赤の抽出、または注釈の読み取り）と解釈（囲み・取り消し線・挿入記号・引き出し線） |
| `evaluate.py` | 正解表（`gt.json`）との突き合わせ |
| `simulate.py` | 予行演習用の模擬朱書きを作る（`python3 simulate.py ../src 出力先 乱数の種`） |
| `gt.json` | 正解表（位置つき） |
| `rules.json` | 紙の場合に登録する全体指示の例 |

## 分かっている限界

- 紙の「ママ」「イキ」は読めないため、修正漏れの疑いとして出る
- 文字の行の真ん中を、行に沿って長く走る引き出し線は、取り消し線と区別できない
- 本文に重なった手書きの注記や、字の端をかすめるだけの斜線は、誤検出や読み取り失敗の原因になる（その場合は人に確認を求める安全側の結果になる）
- 見た目でほとんど差のない差し替え（長音「ー」→漢数字「一」など）は、PDFの文字データで補って検出する。文字データのないPDFでは検出できない
- 段組みの読み順は、すき間で紙面を切り分ける方式（XY-cut）で推定している。複雑な回り込みのレイアウトは未検証
