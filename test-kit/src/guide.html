校正テスト　実施手順書（主催者向け）

目的：朱書き照合ツールの試作が、実際の校正者の筆跡と書き方で正しく働くかを確かめます。 これまでの検証は模擬の筆跡だけで行っており、ここが最大の不確定要素です。結果をもとに、静的なブラウザ版（社外送信なし）の開発に進むかを判断します。

1. キットの中身

ファイル使う人内容
01_初校ダミー.pdf校正者朱書きしてもらう4ページの原稿（チラシ／縦組み／カタログと表／2段組み。内容は架空）
02_赤字指示書.pdf校正者朱書きしてもらう26項目と、その位置の図
03_修正後ダミー.pdf主催者のみ指示を反映した「修正後」。わざと修正漏れ・指示外の変更・展開漏れを混ぜてある
04_正解表.csv主催者のみ全41項目の正解（どの箇所をツールがどう判定すべきか）
tool フォルダ採点する人照合ツールの試作と採点スクリプト（Python）。使い方は tool/README.md
sample_result フォルダ参考模擬の朱書きで予行演習したときの判定結果の画像と採点表
「03_修正後ダミー.pdf」と「04_正解表.csv」は、校正者に見せないでください（普段どおりの朱書きにならなくなるため）。

2. 準備

  • 参加者：3〜5名。書き方の違いを集めるのが目的なので、経験年数や癖が違う人を混ぜてください。
  • 記入者ID：T1、T2…のように記号を割り当ててください（氏名は書かせない）。
  • 印刷：01_初校ダミー.pdf をA4・実際のサイズ（拡大縮小なし）・カラーで人数分。02_赤字指示書.pdf も人数分。

3. 当日の流れ（目安30分）

  1. 指示書の1ページ目を読んでもらう（5分）。「腕前のテストではない」「普段どおりの書き方で」を口頭でも伝えてください。
  2. 朱書き（15〜25分）。指示の順番は自由。分からない箇所は指示書の位置図を見てもらう。
  3. 回収し、スキャンする（次項）。

4. スキャンの方法

  • カラー・300dpi、4ページを1つのPDFに（ファイル名：T1_scan.pdf）。原稿台でも自動給紙でも可。
  • 「白紙除去」「文字くっきり」「傾き補正」などの自動補正は、可能なら切る。
  • （任意）1ページ目をスマートフォンで真上から撮影（T1_photo.jpg）。撮影で使えるかの確認用です。

5. デジタル朱入れ（任意・できる人だけ）

  • Acrobat などで、同じ指示を「01_初校ダミー.pdf」に注釈で入れて保存（T1_digital.pdf）。
  • 使う機能は普段どおりで構いません（取り消し線、テキストの置換・挿入、ノート、フリーハンドなど）。
  • 全体指示（No.04）は、テキストボックスなどに「全体的に「お問い合わせ」→「お問合せ」」のように書くと自動で読み取れます。

6. 回収したファイルの扱い

ダミー原稿なので、社外秘の内容は含まれません（記入者IDも記号です）。次のどちらかで採点します。

  • Claudeに渡す：スキャンしたファイルを会話に添付してもらえれば、採点と、失敗した書き方の分析・ルールの改良まで行います。
  • 自分で採点する：tool/README.md の手順で実行します（Python 3.10以上が必要）。
python3 proofcheck.py ../01_初校ダミー.pdf ../03_修正後ダミー.pdf --scan T1_scan.pdf --rules rules.json --out T1_結果
python3 evaluate.py gt.json T1_結果/findings.json --rules-given --csv T1_採点.csv

7. ツールの判定の種類

記号判定意味
A赤字あり・変更あり指示した箇所が変わっている。中身が指示どおりかは人が確認（デジタル朱入れは指示文と自動照合）
B赤字あり・変更なし修正漏れの疑い
B2同じ赤字が隣の字にもかかる軽い確認
C1全体指示・以下同様で説明できる変更指示外に見えるが、全体指示や以下同様の展開として説明がつく
C2 / C3指示外の変更赤字がないのに変わっている（文字・組み／画像・図版・色・位置）
D全体指示・以下同様の展開同じ語の他の箇所が「展開済み」か「展開漏れの候補」か
E見た目では差が出ない文字の差し替え例：長音「ー」→漢数字「一」。文字データで検出
F指示箇所に結びつかない赤字欄外の注記・印鑑など。人が読む
G全体指示として読み取った注記デジタル朱入れのみ
Mママ・イキどおり変更なしデジタル朱入れのみ（紙は読み取れない）

8. 合格の目安（提案）

  • 重大な見逃しが0件（必須）：修正漏れ・指示外の変更・展開漏れを、ツールが「問題なし」と扱ったもの。
  • 指示の読み取り（26項目）で9割以上が正しく対応づく。
  • 誤検出が1人あたり2件程度まで（多いと現場で使われなくなるため）。

満たせば静的なブラウザ版の開発へ進み、満たさなければ失敗した書き方を分析してルールを改良し、再テストします。

模擬の筆跡は、フォントで書いた文字と、ぶれを加えた直線でできています。判定ルールはこのデータを見ながら調整したため、本物の筆跡では結果が下がる可能性が高いです。それを確かめるのがこのテストです。

10. 分かっている限界

  • 紙の「ママ」「イキ」（変更しない指示）は文字を読めないため、「修正漏れの疑い」と出ます（デジタル朱入れなら読み取れます）。
  • 引き出し線が文字の行の真ん中を、行に沿って長く走ると、取り消し線と区別できません。行間や欄外を通る線は区別できます。
  • 手書きの注記が本文に重なっていたり、斜線が字の端をかすめるだけだったりすると、「修正漏れの疑い」と「指示外の変更」の両方が出ることがあります（人に確認を求める安全側の誤り）。
  • 見た目でほとんど差のない差し替え（長音「ー」→漢数字「一」など）は、PDFの文字データで補って検出します。文字データがない（アウトライン化した）PDFでは検出できません。
  • 処理時間は4ページで約17秒（試作・Python）。ブラウザ版での速度は未検証です。
