# 精度アップの検討（2026年10月31日）

利用者の問い：「チェック項目は本当に今のものだけで精度高くできるのか。一度精度アップの検討をして欲しい。」

模擬データ（文言はすべて架空）での測定と、調べものにもとづいてまとめています。利用者の実データは、作業用の場所が入れ替わって手元にないため、今回は使っていません。

## 1. まとめ

- 精度を左右していたのは、チェック項目の数よりも、照合の仕組みの弱点でした。新しい測り方（架空のカタログに直しを無作為に入れて数える）で測ると、照合の仕方によって、入れた直しの7〜26%を見逃していました。
- 見逃しの原因は4つで、どれも「直しが入った所ほど見落とす」種類です（3章）。試しに直すと、見つける割合は次のように上がり、余分な検出も減りました。自動テスト一式の判定は、直す前と同じです。

| 照合の仕方 | 今（見つけた数） | 余分な検出 | 試しに直した後 | 余分な検出 |
|---|---|---|---|---|
| 旧版＋成果物 | 351/420（83.6%） | 30件 | 418/420（99.5%） | 2件 |
| 同じレイアウトのPDF原稿（注釈なし）＋成果物 | 390/420（92.9%） | 3件 | 405/420（96.4%） | 3件 |
| テキストの原稿＋成果物 | 313/420（74.5%） | 5件 | 418/420（99.5%） | 0件 |

  （直しは14種類×3か所＝42か所の模擬データを10通り。直し方を決めるときに使った5通りと、決めたあとに初めて使った5通りの合計。後者だけでも 100%・96.7%・99.0%）

- チェック項目（観点）の抜けで大きいのは、成果物の中の食い違い（同じ品番・商品名の価格や仕様、目次・参照ページ・注記番号・連番）、計算（税込＝税抜×税率）、組版（禁則・文字の重なり）です。カタログ・チラシで効果が大きいのは、同じ品番・商品名の価格や仕様の食い違いと、税込の計算です（5章）。

## 3. 見逃し・誤検出の原因（照合の仕方ごと）

| # | 照合の仕方 | 原因 | 起きたこと |
|---|---|---|---|
| 1 | テキスト・データの原稿 | どのページに載っているかを、原稿の段落・行が一字一句そのまま含まれるかで決めていた | 直しの多いページが対応から外れ、そのページの直しをすべて見逃した（10通り中4通り。警告「対応する原稿のページが見つかりませんでした」は出るが、気づかないと見逃しになる）。直しが多いほど見逃す |
| 2 | 旧版との比べ合わせ | 記号だけの変化（「、」→「。」・「※」が消えた）と、全角・半角の変化を出さない作りだった | 記号 1/30、全角・半角 0/30 |
| 3 | 旧版との比べ合わせ | 1行まるごと消えたとき、その行の字が、離れた所の同じ字の並び（表の中の商品名・日付など）に当たった | 消えた行が別の所に示され、当てられた所に意味のない違いが出た（余分な検出30件のほとんど） |
| 4 | 同じレイアウトのPDF原稿（字の形で比べる） | ①成果物にない文字のかたまりを、原稿への「赤以外の書き込み（鉛筆のメモなど）」とみなして、黙って照合から外していた（紙の原稿のメモを無視するための決まりが、PDFの印刷された字にも当たっていた）。②形がほぼ同じ字（ー→一・全角⇔半角のかっこ）は形では見分けにくい。語の終わりの「ー→一」を見る決まりがなかった | ①注記3行がまとめて消えても1件も出なかった。②長音17/30・記号20/30 |

## 5. チェック項目（観点）の抜け

印刷物の校正は、原稿との照合と体裁の整備を含むとされます。チラシでは誤字脱字・電話番号やURLなどの掲載情報・書体の統一・レイアウトのずれや要素の重なりを、素読みでは数字・記号・固有名詞・単位・表記の統一を、カタログでは商品マスタとの価格・品番・仕様の突き合わせを確かめる、という例が挙がっています（出典は末尾）。これを観点ごとに分け、今の対応を整理しました（○ 対応・△ 一部・× なし）。

| 分類 | 観点 | 今 | メモ |
|---|---|---|---|
| A 原稿・旧版と照らし合わせる | 文字・数字・記号・全角半角 | ○ | 4章の直しで、旧版との比べ合わせの記号・全角半角も○ |
| | 書式（太字・大きさ・色） | △ | 指示がある所は自動で判定。指示のない書式の変化は、字の形で比べる紙・PDF原稿だけ |
| | 改行・段落 | △ | 紙のスキャンは既知の限界 |
| | 画像・図版の差し替え・位置 | △ | 紙・PDF原稿は形で比べる。レイアウトが違う原稿では見ない |
| | 表（商品マスタ）・グラフ | ○ | |
| | 文字データのない所（アウトライン・画像の文字） | △ | OCR。似た形の字は同じとみなす |
| B 成果物の中の食い違い | 表記ゆれ | ○ | |
| | 同じ品番・商品名の価格・仕様の食い違い | × | カタログの重大な誤りに直結 |
| | 目次の見出し・ページ番号と本文、参照ページ（「→P.12」）、ノンブル・柱 | × | 冊子向け |
| | 注記番号（※1）と注記・図表番号の対応、箇条書きの番号の連番（①②④） | × | |
| C 事実・計算 | 日付と曜日・存在しない日付・電話番号・郵便番号 | ○ | |
| | 税込・税抜の計算、合計・割引 | × | |
| | 和暦と西暦の対応、単位の取り違え・混在（mm・cm） | × | |
| D 日本語 | 誤字・誤用・送りがな・助詞・敬語・ら抜き・重複表現・異字同訓 | ○ | 決まった一覧と辞書の範囲 |

| F 印刷データ（入稿） | 書体の埋め込み・画像の解像度・カラーモード・塗り足し | × | 印刷会社のデータチェックの領分。対象外にする案 |

## 6. 改善案（優先順）

### 優先1：4章の試しの直し（A-1〜A-5）を本体に入れる

- メリット：見逃しが減る（旧版 83.6%→99.5%、テキスト 74.5%→99.5%、PDF原稿 92.9%→96.4%）。余分な検出も減る（旧版 30件→2件）。自動テスト一式の判定は変わらない
- デメリット：旧版との比べ合わせで、記号の変化・全角半角の変化の項目が増える（本当の変化だが、件数は増える）。実データでは確かめていない（入れる前に、カタログの旧版・成果物をもう一度入れていただければ確かめられる）

### 優先2：仕組みを足す

| # | 案 | メリット | デメリット | 手間 |
|---|---|---|---|---|
| B-1 | PDF原稿（注釈なし・文字データあり）では、字の形に加えて文字データでも比べる | 残った弱点（形が同じ記号・全角半角）がなくなる見込み | 赤字を描き込んだ原稿では、赤字どおりの変化と文字の違いが重なるので、出し分けの整理が要る | 中 |
| B-2 | 紙のスキャンでも、「赤以外の書き込み」とみなした所を捨てずに「人が確認」に出す | 黙って照合から外す所がなくなる | 鉛筆のメモが多い原稿では、確認の項目が増える | 小 |
| B-3 | 直しを無作為に入れる測定を自動テストに加え、縦組み・回転した字・別の書体・紙のスキャンにも広げる | 想定の外の弱点を見つけ続けられる | 自動テストの時間が数分増える | 小〜中 |

### 優先3：チェック項目を足す（カタログ・チラシ向けに効果の大きい順）

| # | 案 | メリット | デメリット | 手間 |
|---|---|---|---|---|
| C-1 | 同じ品番・商品名の価格・仕様の食い違い（成果物の中で） | 価格違いという重大な誤りを、原稿がなくても拾える | セット価格・期間限定価格など、意図して違うものも出る（「確認だけ」に出す） | 中 |
| C-2 | 税込・税抜の計算（「税込X円（税抜Y円）」のように並ぶとき、X＝Y×1.1（軽減税率は1.08）か） | 計算の誤りを確実に拾える | 端数の処理（切り捨て・四捨五入）の違いを認める必要がある | 小 |
| C-3 | 注記番号（※1）と注記の対応、箇条書きの番号の連番 | 番号の抜け・重なりを拾える | 番号の付け方の流儀によっては誤検出になる | 小 |
| C-4 | 目次・参照ページ・ノンブル | 冊子の参照の誤りを拾える | チラシ・1枚物には不要 | 中 |
| C-5 | 禁則（行頭の句読点・閉じかっこ） | 組版の見落としを拾える | 組版ソフトが処理済みのことが多く、効果は限られる | 小〜中 |
| C-6 | 文字の重なり・はみ出し | レイアウトの崩れを拾える | デザインとして重ねたものも出る | 中 |

対象外にする案：入稿データのチェック（印刷会社のデータチェックの領分で、専用の道具がある）、文の意味のねじれ（生成AIを使わない決まったルールでは誤検出が多い）。

## 7. この検討の限界（自己分析）

- 測った文書は、架空・横組みだけ・IPAゴシック1書体・2ページです。縦組み・回転した字・画像の中の字・実際のDTPでの文字の送り（行の組み替え）は含みません。
- 紙のスキャン（手書きの赤字）は、今回の無作為の直しの測定に入れていません（2-1の41項目×8通りの結果だけです）。
- 直し方を決めるときに、最初の5通りを見ながら決めました。決めたあとに初めて使った5通りでも、同じくらい見つけています（100%・96.7%・99.0%）。それでも、この文書の作りに合わせ込んだ可能性は残ります。
- 1行に何か所も直しが集まる場合は、少ししか含みません。
- 実データ（カタログ）では、作業用の場所が入れ替わって手元にないため、試しの直しの影響を確かめていません。
