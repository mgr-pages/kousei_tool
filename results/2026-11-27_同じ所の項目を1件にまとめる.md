# 同じ所の項目を1件にまとめる（2026年11月27日）

依頼：同じ所に、文字の項目と見た目の項目が重なって出る所が残っている。同じ箇所への指摘はひとつにまとめる。精度は保ったまま、なるべく件数を少なく。

## 1. まとめ方（`analyze.js` の `mergeSame`）

- 対象：旧版との比べ合わせの項目（文字の違い・見た目の違い・移動・図形の文字）
- 同じ所：項目の枠（違う所ごとの枠）どうしが、重なるか 2pt 以内に接する。つながるかぎりまとめる
- 上限：まとめた枠がそのページの 15% を超えるならまとめない（1件に入れすぎない）
- まとめた項目：中の変化を位置の順に、種類の札（文字・見た目・移動・図形の文字）を付けて並べる。枠は違う所ごとにすべて描く
- まとめないもの：成果物だけで見るチェック（観点が違う。別の設定で外せる）・注釈の違い

## 2. 候補の比べ（実データ：表裏2ページ。数はまとめ方を試した結果）

| まとめ方 | 旧版比較の項目 | 指摘漏れ | 1件の中の最大 | 備考 |
|---|---|---|---|---|
| まとめない（直す前） | 93件 | 0 | — | |
| 枠が接するものを上限なしでまとめる | 32件 | 0 | 24 | ページの 1/4 を超える項目が2件できる（大きな移動の範囲が、中の変化を次々に取り込む） |
| 上限 ページの25%（まとめた枠が超えない） | 36件 | 0 | 24 | |
| **上限 ページの15%（まとめた枠が超えない）** | **42件** | **0** | 24 | 採用。いちばん大きい1件はページの 13%（書き直した所が集まった一画） |
| 上限 ページの10% | 56件 | 0 | 13 | |
| 上限 ページの5% | 66件 | 0 | 12 | |

## 3. 結果（同じ実データ。ツールの出力）

| | 直す前 | 直した後 |
|---|---|---|
| 項目（全体） | 116件 | **65件** |
| うち旧版との比べ合わせ | 93件 | **42件**（うち、まとめた項目 10件） |
| 正解 40か所のうち見つけた | 40 | 40（指摘漏れ 0） |
| いらない指摘の候補 | 6件 | 5件 |
| ページの 1/4 を超える枠 | 0件 | 0件 |

- 成果物だけで見るチェック（22件）のうち、旧版との比べ合わせの項目と同じ所にあるものは 18件あるが、今回はまとめていない（上の理由）

## 4. テスト

- 移動の試験（`test/move/evaluate.py`）は、まとめた項目を中の項目に分けて数えるようにした（まとめても中身はそのまま残るので、同じ見方で確かめる）。すべて合格
- テスト一式（`test/suite.sh`）：すべての試験で、直す前と同じ成績（悪くなった所なし）
- 画面：いちばん多くまとめた項目（中に24件）も、種類の札を付けて変化を上から順に並べて表示できることを確かめた（中身は省かずに全部出すので、縦に長くなる）

## 5. 追記：成果物だけで見るチェックもまとめる（同日）

依頼：成果物だけで見るチェック（ページの端の文字・表記ゆれなど）も、同じ所なら旧版との比べ合わせの項目にまとめる（質問への回答 A）。

- 旧版との比べ合わせの項目と同じ所（上と同じ決め方）にあるものを、その項目に入れる。成果物だけで見るチェックどうしだけではまとめない
- 重さ：中に「直す必要がありそう」なチェックがあれば、まとめた項目を「直す必要がありそう」の「変わった所と誤りの可能性」に出し、そのチェックを赤い印で示す（まとめても軽くしない）
- 詳細設定：外した種類のチェックは、まとめた項目の中にも出さない。中のどれも出さない設定なら、項目ごと出さない
