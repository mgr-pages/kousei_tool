# 画像だけのPDF原稿で誤検出が大量に出る件（2026年11月18日）

注釈（コメント）付きのPDFを原稿、注釈のないPDFを成果物として入れると、誤検出が大量に出た件の分析と対応の記録です。利用者のファイルはリポジトリに入れていません（数だけを書きます）。

## 1. 起きたこと

2つのPDFは、どちらも1ページで、ページ全体が1枚の画像（文字データなし）です。画像のデータは同じで、違いは原稿の側の注釈3つ（円とコメント・線・テキストボックス）だけでした。それでも結果は37件（うち「指示にない変更」31件）、照合に92秒かかりました。正しくは「注釈の指示がまだ直っていない」だけです。

## 2. 調べたこと（数えて確かめたもの）

| 確かめたこと | 結果 |
|---|---|
| 原稿のページの扱い | 「紙のスキャン」。注釈があっても文字データがないと紙のスキャンとし、ページを覆う画像があるとスキャンとしていたため |
| 位置合わせ（突き合わせ）の正確さ | ずれは 0.1画素未満。31か所すべて、ずらさないときがいちばん一致した（位置合わせの誤りではない） |
| 31か所の画像の違い | 原稿を 300dpi で描いて成果物に合わせて縮めた画像と、成果物を 200dpi で描いた画像で、小さい字の所の明るさの差が平均 12〜33（255段階）。同じ 200dpi で直接描くと、画素が完全に一致する（差 0） |
| 2段目の確かめ | 見逃しを避けるため「違うと確かめられない候補は残す」作り。描き方の違いで字の形・OCR の字が揺れた所が残った |
| 描画の一致率（注釈を消して同じ解像度で描き、インクのある画素のうち同じ色の割合） | 紙のスキャン33ページ：0.2〜3.3%。同じデータから書き出したPDF：91.5〜100%（届いたPDFは 100%） |

## 3. 原因

比べ方を、ファイルの見た目の特徴（文字データがあるか・ページを覆う画像があるか）で決めていたことです。描画がまったく同じで、いちばん確かな比べ方（画素の一致）が使えるのに、いちばん不確かな比べ方（紙のスキャン用：描き直し・縮小・字の形・OCR）に回していました。ご指摘の「1画素レベルにも反応している」は、この経路で、描き方の違いを違いとしていたことに当たります（位置合わせ自体は正確でした）。

## 4. 直し方の候補

| 候補 | メリット | デメリット |
|---|---|---|
| A. 比べ方を測って決める（原稿を注釈なしで成果物と同じ解像度で描き、画素がほぼ一致すれば、同じデータのPDFとして確かな比べ方を使う） | 原因そのものを直す。画像だけのPDF全般（デザインを画像で書き出したもの）に効く。紙のスキャンは一致率がほぼ0なので、扱いは変わらない | 原稿のページごとに小さく描いて比べる手間（50dpi。1ページ1秒未満） |
| B. スキャンの比べ方の感度を下げる（小さい違い・OCR の1字違いを出さない） | 紙のスキャンでも誤検出が減る | 本当の1字の直し（「1」→「7」など）も見逃す。いちばん避けたい見逃しが増える。経路の誤りは残る |
| C. スキャンの比べ方の中で描き方をそろえる（同じ解像度で描く） | PDFの原稿では差が小さくなる | 本物の紙のスキャンには効かない。A なら画素の一致という確かな証拠まで使えるので、A に含まれる |
| D. 原稿の種類を利用者が選ぶ | はっきりする | 手間が増え、選び間違いも起きる。画面を簡素にする方針と合わない |

**選んだもの：A**（あわせて、注釈の読み方の同じ種類の弱さを直す：下の2）。

## 5. 直したこと

1. **比べ方を測って決める**（`analyze.js` の `sameSource`）：PDFの原稿のページを注釈なしで成果物と同じ解像度（50dpi）で描いて重ね、インクのある画素の半分以上が同じ色なら、同じデータから書き出したものとする。注釈があれば注釈PDF（注釈を指示として読み、注釈を消した描画を画素で比べる）、なければスキャンでないPDFとして比べる
2. **テキストボックスの注釈は、打ち込んだ文字を注釈のデータから読む**（`marks.js` の `PC.typedNote`）：これまでは、描いた枠と字の形を赤字の印として読んでいたため、1つの注釈が4件（囲み・取り消し線・注記2つ）に分かれていた。打ち込んだ文字は、同じ行の近くの指示（取り消し線など）に添える。全体指示（「全体…「A」→「B」」）は、これまでどおり読む
