# 処理時間の目安と、画面・仕組みの見直し（2026年11月11日）

利用者からの依頼は次の2つです。利用者のファイルはリポジトリに入れていません。ここには件数と時間だけを書きます。画面写真と例は架空の模擬データ（`testdata`）のものです。

1. 校正を始めるときに、あとどれくらいかかりそうかの目安（ざっくり何分）を出せるか
2. アプリデザイナーとアプリ制作ディレクターの観点で、アプリの仕組みとデザインを検討する。方向性は「直感的に操作できるように、シンプルに」

## 1. 処理時間の目安（搭載したもの）

### しくみ

- **照合の前**：入れたファイルの種類・ページ数・ページの大きさから見積もり、照合ボタンの横に「目安：約N分」を出す（1分未満は「1分以内」）
- **照合中**：進み具合（％）から求めた残り時間と、照合前の見積もりを混ぜて出す。進むほど進み具合のほうを重く見て、急に変わらないようにならす。表示は1秒ごとに更新し、「あと約N分」「あと1分以内」「まもなく終わります」（残り20秒未満）と出す
- **原稿の種類**は、照合と同じ見分け方で1ページ目から決める（注釈と文字データがある → 注釈を入れたPDF、ページを覆う画像がない → スキャンでないPDF、それ以外 → 紙のスキャン）

見積もりに使う時間（検証環境で1件ずつ測った値。A4 の1ページあたり。ページの大きさに比例させ、はじめに2秒を足す）：

| ファイル | 1ページあたり |
|---|---|
| 原稿：紙のスキャン | 約13秒（旧版もあるとき 約10秒） |
| 原稿：スキャンでないPDF（注釈なし） | 約8秒 |
| 原稿：注釈を入れたPDF | 約4秒 |
| 原稿：データ（Excel・Word など） | 約0.5秒（ファイルごとに1秒を足す） |
| 成果物 | 約0.5秒 |
| 旧版 | 約1.5秒 |

### 結果（検証環境で実行）

| データ | 照合前の目安 | 実際 |
|---|---|---|
| 紙のスキャン4ページ＋成果物 | 約1分 | 52秒 |
| 紙のスキャン＋成果物＋旧版（各4ページ） | 約1分 | 52秒 |
| 注釈を入れたPDF 4ページ＋成果物 | 1分以内 | 18秒 |
| スキャンでないPDF 2ページ＋成果物 | 1分以内 | 20秒 |
| 紙の赤字原稿＋旧版の模擬データ（各1ページ） | 1分以内 | 12秒 |
| 旧版＋成果物（各4ページ） | 1分以内 | 7秒 |
| 名刺（差し込み。表＋成果物12ページ） | 1分以内 | 7秒 |
| データの原稿5つ＋成果物 | 1分以内 | 3秒 |
| 成果物だけ2ページ | 1分以内 | 3秒 |
| 利用者のチラシ（紙の赤字原稿4ページ・成果物2ページ・旧版2ページ） | 約1分 | 59秒 |

照合中の表示の例（紙のスキャン4ページ）：10秒「あと1分以内」→ 34秒「まもなく終わります」→ 52秒で完了。利用者のチラシ：5秒「あと約1分」→ 20秒「あと1分以内」→ 36秒「まもなく終わります」→ 59秒で完了。

### 作る途中で見つけて直したこと（自己点検）

| # | 見つかったこと | 直したこと |
|---|---|---|
| 1 | 文字の層があるスキャン（スキャナーで文字を読み取ったPDF）を「スキャンでないPDF」と見なし、利用者のチラシで目安が短すぎた（見積もり24秒・実際59秒） | 照合と同じ見分け方（ページを覆う画像があるか）で種類を決める |
| 2 | スキャンでないPDFの時間を少なく見ていた（3秒／ページ。実測は8〜9秒） | 実測に合わせた |
| 3 | 照合の終わり（結果を表示している間）に「完了（まもなく終わります）」と出ていた | 「結果をまとめています」と出し、残り時間を付けない |

### 限界

- パソコンの速さで変わります（検証環境は4コア）。照合前の目安は外れることがありますが、照合中は進み具合で見直します
- 照合の最後の工程（表の照合・OCR）は進み具合の割合が小さいため、「まもなく終わります」のあと十数秒かかることがあります

## 2. 画面・仕組みの見直し

### 2-1. 前提（だれが・何のために使うか）

- **使う人**：印刷物・販促物の制作で、校正を確かめる人（ディレクター・オペレーター）
- **したいこと**：赤字が漏れなく直っているか／指示にない変化がないか／基本的な誤りがないかを、短い時間で確かめて記録を残す
- **大事にすること**：見落としを出さない（いちばん大事）、迷わない、待たされない

### 2-2. 今の流れと、残したい良い所

流れ：①ファイルを入れる → ②照合（待つ）→ ③結果の概要を見る → ④1件ずつ確かめて判定する → ⑤残す（CSV・印刷）→ 新しい校正

- 入れたファイルの組み合わせで、チェックの仕方が自動で決まる（やり方を選ばなくてよい）
- 外部に送らないことが、いつも画面の上に見えている
- 「直す必要がありそう」と「確認だけ」に分け、直す必要がありそうなものから並ぶ
- 違う字だけに色を付け、切り抜きで原稿と成果物を並べる
- 判定（OK・要修正・保留・メモ）がブラウザに残り、CSV・印刷で出せる

### 2-3. 見つけた課題（段階ごと）

| 段階 | 見つけたこと | 観点 | 対応 |
|---|---|---|---|
| ①入れる | 何も入れていないのに「新しい校正」が出ていた（ボタンの見た目の設定が、隠す設定に勝っていた） | 不具合 | 直した |
| ①入れる | 「チェックの仕方」の4つの札が、押せるボタンに見えるが押せない。同じことを説明文・照合ボタンの名前でも伝えていて、3回重なる | 見た目と働きの食い違い・重なり | 提案B |
| ②待つ | あとどれくらいかかるか分からない | 状態が見えない | 入れた（目安） |
| ②待つ | 途中でやめられない（ページの再読み込みしかない） | 手戻り | 入れた（中止） |
| ②待つ | 照合中にファイルを足すと照合ボタンが押せるようになり、二重に照合できた | 不具合 | 直した |
| ③見る | 見出しの横の1段落に、時間・全体の直し・注意がつながっていて読みにくい | 読みやすさ | 直した（1行ずつ） |
| ③見る | 種類が多い（概要のカードは最大17種類。ふだんは5〜9）。名前が長く、カードの中で3行に折り返す。枠の色は15色（模擬データの例で凡例11色） | 判断の負担 | 提案C |
| ③見る | カードを押すと「その種類を外す」。よくある「その種類だけを出す」と逆 | 思い込みと逆 | 提案A |
| ④確かめる | どこまで確かめたかが分からない | 見落とし防止 | 入れた（確認 n / N件） |
| ④確かめる | 次に見る項目を、スクロールして探す | 手数 | 入れた（次の未確認へ） |
| ④確かめる | マウスだけで操作するため手数が多い | 手数 | 入れた（キー操作） |
| ④確かめる | ページの表示が小さく、拡大できない（切り抜きはある） | 確かめにくさ | 提案E |
| ④確かめる | 薄い字（ページの番号・「またはここへドラッグ」など）が読みにくい（白地との濃さの比 2.9:1） | 読みやすさ | 直した（4.6:1。読みやすさの目安は 4.5:1 以上） |
| ⑤残す | 結果を保存して、あとで開く・人に渡す手段がない（判定はブラウザに残るが、結果は照合し直し） | 仕組み | 提案F |
| ⑤残す | 未確認の項目が残ったまま CSV・印刷できる | 見落とし防止 | 提案G |
| 全体 | 照合が画面と同じ流れで動くため、重いページの間は画面の反応が鈍い | 仕組み | 提案H |
| 全体 | 詳細設定が39項目ある（閉じてあり、既定はすべてオン） | 情報の量 | 提案I |

### 2-4. シンプルにするための原則

1. 1つの画面でいちばん目立つのは「次にすること」1つ（入れる → 照合 → 未確認を確かめる）
2. 状態をいつも見せる（何をしているか・あとどれくらいか・どこまで確かめたか）
3. 押せる物だけを、押せる見た目にする
4. 判断の言葉と色を少なくそろえる（直す必要がありそう／確認だけ／自動で確認済み）
5. 機能は減らさず、目に入る物を減らす（ふだん使わない物は畳む・選んだときだけ出す）

### 2-5. 今回入れたもの（すぐにできて、危なくないもの）

| 入れたもの | 内容 |
|---|---|
| 処理時間の目安 | 上の1. |
| 中止 | 照合中は「新しい校正」の代わりに「中止」を出す。押すと次の区切りで止まり（模擬データで約1秒）、入れたファイルはそのまま。もう一度押すと最初から照合する |
| 二重の照合を防ぐ | 照合中にファイルを足しても、照合ボタンは押せないまま |
| 表示の不具合 | 何も入れていないときは「新しい校正」を出さない |
| お知らせを1行ずつ | 結果の見出しの横は「ページ数・時間」だけにし、全体の直し・注意・詳細設定で外した件数は、その下に1行ずつ並べる |
| 確認の進み具合 | 一覧の上に「確認 n / N件」と進み具合の棒（OK・要修正・保留を付けた数。参考は数えない）。要修正・保留の数も添える |
| 次の未確認へ | まだ何も付けていない次の項目へ移る（すべて付けたら、そう知らせる） |
| キー操作 | 項目を選んでいるとき：↑↓ 前・次の項目、1 OK・2 要修正・3 保留（付けると次の項目へ）。メモの欄では働かない。説明は、選んだ項目の中にだけ小さく出す（画面を増やさないため） |
| 薄い字を読みやすく | 薄い灰色の字を少し濃くした |

確かめたこと（ブラウザ）：何も入れていないときに「新しい校正」が出ない／照合中は「中止」だけが出て、照合ボタンは押せない／中止で約1秒で止まり、エラーは出ず、もう一度照合できる／お知らせが1行ずつ出る／「確認 0 / 48件」から、次の未確認へ・1・2・3・↑↓ で判定と移動ができ、件数が合う／メモの欄で「1」「2」を打っても判定は変わらない／「確認済み（OK）を隠す」がオンのとき、1 を押すと項目が消えて次が選ばれる／幅1280・1400で一覧の上の操作が1行に収まる。

### 2-6. 次の提案（決めていただきたいもの）

| 案 | 内容 | メリット | デメリット | 作る量 | おすすめ |
|---|---|---|---|---|---|
| A | 概要のカードを押したら「その種類だけ」を出す（もう一度押すと全部に戻る） | よくある絞り込みと同じ動きで迷わない。1種類ずつ確かめるのが1回で済む | 今の「外す」に慣れた人には動きが変わる。2種類以上を一緒に見るには、もう1つ押し方が要る（Ctrl を押しながら など） | 小 | 入れる |
| B | 「チェックの仕方」の4つの札をやめ、照合ボタンの上に1文だけ残す | 押せない札がなくなり、画面が1段短くなる。伝わる中身は同じ（照合ボタンの名前も、入れたものに合わせて変わる） | 4通りのやり方があることが、画面だけでは分からなくなる（利用ガイドの表で補う） | 小 | 入れる |
| C | 種類の分け方と色を少なくする。概要は「直す必要がありそう」「確認だけ」の中に件数の多い順に並べ、色は4つ（赤＝直す必要がありそう、橙＝変化の確認、緑＝赤字どおり・自動で確認済み、灰＝参考）にする。細かい種類は項目の札に残す | 凡例とページの枠の色の意味がすぐ分かる。概要が短くなる | 種類ごとの色で見分けていた人には変わる。利用ガイドの表を作り直す。細かい種類は札の文字で見ることになる | 中 | 試作を見てから決める |
| D | 一覧を詰める（選んでいない項目は切り抜きを小さく） | スクロールが減り、全体を見渡せる | 切り抜きを見ないまま OK にしやすくなる（見落としの元） | 小 | 見送り（見落とし防止を優先） |
| E | ページの表示を拡大できるようにする（ボタン・ホイールで拡大、選んだ項目の所へ寄る） | 小さな字・図版の変化を、その場で確かめられる | 操作が1つ増える | 中 | 切り抜きで足りていなければ入れる |
| F | 結果と判定を1つのファイルに保存し、あとで開く・人に渡す | 照合し直し（1〜数分）が要らない。担当の引き継ぎができる | ファイルにページの画像が入り、大きくなる（数十MB）。原稿・成果物の画像が入るため、渡し方に注意が要る | 大 | 引き継ぎに使うなら |
| G | 未確認の項目が残ったまま CSV・印刷するときに、「未確認が n件あります」と知らせる | 確かめ忘れを防ぐ | 先に CSV を出してから確かめる使い方では、知らせがわずらわしい | 小 | 入れる（知らせは1回だけ） |
| H | 照合を画面の裏側（Web Worker）で動かす | 照合中も画面がなめらかで、中止がすぐ効く | 作り替えが大きく、不具合が入りやすい。中止は今でも約1秒で効き、目安も出るため、効果が小さい | 大 | 見送り |
| I | 詳細設定に、おすすめの組み合わせ（すべて／原稿との照合だけ／文字・表記だけ）を置く | 39項目を見なくても、目的で選べる | ボタンが増え、何が外れるかが見えにくい。今も照合のあとで切り替えられ、既定はすべてオン | 小 | 見送り（使い方を見てから） |

## 3. 限界（自己分析）

- 見直しは、模擬データと利用者のチラシでの画面、コードを見て行いました。実際に使っている人の操作を見たものではないため、「どこで迷うか」は推測を含みます（特に提案C・E・Fの必要度）。使う人の声で優先度を決め直すのがよいと考えます
- キー操作は、知っている人だけが使う機能です（選んだ項目の中にだけ説明を出しています）
- 処理時間の目安は、検証環境の速さに合わせた見積もりです（照合中は進み具合で見直します）
