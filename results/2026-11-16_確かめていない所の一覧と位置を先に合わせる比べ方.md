## 2. 文字として確かめていない所の一覧

文字が図形になっていて（アウトライン化した見出し・ロゴなど）文字データのない所は、文字としては確かめられません。今までは、そうした所があっても何も示していませんでした。今回、経路ごとに「本当に確かめていない所」だけを一覧に出すようにしました。

| その所を照合した経路 | 扱い |
|---|---|
| 見た目で比べたページ（同じレイアウトの原稿・注釈PDF・紙の赤字原稿） | 出さない（見た目の違いは比べてある） |
| 文字で比べたページ（データ・ラフの原稿） | 「文字として確かめていない所」（OCRで読んで比べた所は除く） |
| 原稿の当たらない所（成果物だけ） | 「文字として確かめていない所」（成果物だけのチェックをしていない） |
| 原稿の当たらない所で、旧版があり、ページの大きさ・位置がそろう | その所の図形（輪郭ごとの範囲と塗りの色）を旧版と成果物で突き合わせる。同じなら出さない（前回のまま）。違えば「前回から変わった（図形の文字）」として、違う所に枠を付ける |
| 同上で、ページの大きさ・位置がそろわない | 「文字として確かめていない所」 |

一覧では、ページごとに1件にまとめ、そのページの該当する所すべてに枠を付けます（大きい所を代表にする）。お知らせにも合計の数を出します。

### 見つけ方（`src/js/content.js` の `PC.vectorParts`・`PC.vectorSpots`）

最初は、描いた絵のうち文字データの字に重ならないインクを探す方法（OCRの候補探しと同じ）を試しましたが、実データのカタログで写真・アイコン・製品の絵にも多く当たり、使えませんでした。そこで、PDFの描画命令から直接探すことにしました。

1. 塗りつぶすパスを、ひと続きの輪郭ごとの範囲にする（四角形・線だけのパス・切り抜き用のパスは除く）。塗りの色も持たせる
2. 文字データの字の下にある部品を除く（文字データのある字の飾りなど）
3. 地（中に部品を2つ以上含み、それらより3倍以上大きい図形：囲み・地の丸など）を除く
4. 重なる・とても近い部品を1字にまとめる（偏とつくり・点・字の穴）
5. 同じ色で、高さの近い字が、字の大きさほどの間で並ぶものを行にする（「ー」「、」のような小さな字は、となりの字の高さの中にあればつなぐ）。3字以上で、同じ形だけが並ぶもの（点線・模様）でない行を残す
6. 重なって並ぶ行を、1つの所（段落・ロゴ）にまとめる

色をそろえる条件は、実データで製品の絵（色の多い面の集まり）を1つの「行」にしてしまったため入れました。入れたあと、実データ（カタログ20ページ・チラシ・名刺など26ページ）で枠を目で確かめ、枠はロゴ・バッジ・シリーズ名など、文字を図形にした所に付くことを確かめました（寸法図の一部に1か所、図の部品に付いたものがありました）。

見つけられないもの：写真などの画像の中の文字、字の部品が3つ以上並ばないもの（2字のロゴなど）。

## 3. 見つかった見逃しと、旧版との比べ方の直し

### 3-1. 旧版も成果物も図形の文字だった所の変化（見逃し）

原稿なしで旧版と成果物を比べる経路は文字データで比べるため、旧版も成果物も文字が図形になっている所（ロゴ・アウトライン化した見出しの中の価格など）が変わっても、何も出ませんでした（片方だけに文字データがあるときは、OCRで読んで比べていました）。上の一覧の処理で、その所の図形を旧版と成果物で突き合わせるようにし（4-2）、違えば「前回から変わった（図形の文字）」として、違う所に枠を付けて出すようにしました。新しい試験（`testdata/outline` の2つの版、小さな字の2つの版）で、4か所とも出ることを確かめました。

### 3-2. 消えた字の印の位置（原則3：並びより位置を先に）

旧版＋成果物で見逃していた4か所は、すべて「消えた字」でした。消えた所の印を、字の並びで隣になった成果物の字の前に付けていたため、行の終わりで消えた字の印が次の行の頭に付き、見逃し（と、行の頭の余分な検出）になっていました。旧版と成果物でページの大きさ・位置がそろっていれば、旧版でその字があった位置に印を付けるようにしました。

### 3-3. 同じ位置の同じ字を、並びより先に対応づける（原則3）

残った余分な検出は、同じ字の並びがページに2回ある所で、字の並びだけの対応づけが「どちらが消えた（入った）か」を取り違えたものでした。旧版と成果物が同じレイアウトのときは、字の並びで対応づけたあとに、次の直しをするようにしました（`analyze.js` の `posFirst`）。

- 「消えた」とした旧版の字と同じ字が、成果物の同じ位置（写した位置から字の大きさの半分以内）にあれば、その字どうしを対応づける。その成果物の字が別の位置の旧版の字に対応づいていたら、その旧版の字を「消えた」にする
- 「入った」とした成果物の字と同じ字が、旧版の同じ位置にあり、その旧版の字が別の位置の成果物の字に対応づいていたら、入れ替える

これで余分な検出は 4件 → 0件 になりました（3-2 のあと 7件 → 4件、3-3 のあと 0件）。

## 4. 実物の版どうしでの見直し（図形の文字の比べ方）

### 4-1. 最初の方式（描いて画素で比べる）の問題

最初は、図形の文字の所を旧版と成果物で描いて画素で比べていました。実物のカタログ（旧版→新版、20ページ）で照合すると、「前回から変わった（図形の文字）」が22件出ました。旧版と新版を並べて目で確かめると、製品写真が差し替わった所（変わったのは写真で、図形の文字ではない）と、目で見て同じ所（書き出し直しで図形がわずかにずれた所、透明の重なりの描き方の揺れ）でした。

画素の差の強さ・まとまりの大きさで見分けられるかも測りましたが、描き方の揺れの一部（バッジ）は、6pt の字の1字の変化と同じくらいの違いになり、見分けられませんでした（300dpi で強い差の画素：小さな字の変化 38〜42、揺れ 19〜27）。

### 4-2. 図形そのものを突き合わせる方式に変更

PDFの描画命令にある図形の部品（輪郭ごとの範囲と塗りの色）を、旧版と成果物で突き合わせるようにしました（原則2「確かな情報から使う」）。範囲が 0.25pt 以内・塗りの色が 8 以内でそろう部品を同じとし、相手のない部品を近いもの（3pt 以内）どうしでまとめて、変わった所にします。どの辺も 0.3pt に満たない部品（グラデーションを細い帯で描いた所の、見えない切れ端）は比べません（実物で、旧版にだけある大きさ 0.06×0.02pt の切れ端が2件の違いになっていたため）。
